# 发布目录多路径配置需求

## 需求背景
原有的「默认部署路径」只有一个文本输入，无法满足一台服务器上存在多个部署目标路径的场景。

## 设计方案

### 服务器配置层面
| 字段 | 说明 |
|------|------|
| `defaultRemotePath` | **默认打开目录**：连接后默认展示的远程目录（类似 FileZilla 的行为） |
| `deployPaths[]` | **发布目录列表**：实际部署文件的目标路径数组，支持多个，第一个为默认 |

### 服务器编辑弹窗
- 「默认打开目录」文本输入（原字段改名）
- 「发布目录」列表区域：
  - 可添加多个路径
  - 支持**拖拽排序**改变顺序
  - 第一个标记为「默认」
  - 支持删除
  - 回车快捷添加

### 部署弹窗
- 「远程路径」改为「发布目录」下拉选择框
- 数据源为当前选中服务器的 `deployPaths` 数组
- 默认选中第一个
- 切换服务器时自动联动更新下拉选项
- 浏览按钮选择的路径追加为临时选项

### 远程浏览器
- 起始路径使用 `defaultRemotePath`（默认打开目录）
- 选择目录后追加到发布目录下拉框

## 数据结构变更
```json
{
  "id": "server-xxxx",
  "name": "同仁堂生产",
  "host": "192.168.1.15",
  "defaultRemotePath": "/docker/nginx/www",
  "deployPaths": [
    "/docker/nginx/www/tongrentang/",
    "/docker/nginx/www/portal/",
    "/docker/nginx/www/admin/"
  ]
}
```

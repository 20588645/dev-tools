# 系统设置页面迁移决策

> 状态：PG0～PG5 全部完成，自动验证与清理后真实 Tauri E2E 均已通过
> 关联评估：[assessment.md](./assessment.md)
> 方向确认日期：2026-07-29
> 正式实现状态：Phase 5-2 系统设置迁移 Gate 已关闭
> 组件架构专项：Settings 自动验证及连接正式 Sidecar 的网页人工验收已完成；通知与 Tauri 壳能力合并到专项最终 Smoke Test
> 原型：[settings-l2.html](../../../../design-preview/settings-l2.html)

## 1. 用户确认

用户已确认采用 PG2 推荐方案：

- 优化等级选择 **L2：分类式系统控制台**。
- 制作亮色、暗色、1280 × 720 默认窗口和 900 × 600 窄窗口 HTML 原型。
- 菜单排序只使用明确的上移/下移按钮；真实 Tauri E2E 发现拖拽不可靠且不易操作，已移除拖拽入口。
- Live2D 与点击粒子移入“实验功能”，默认关闭，不作为常规设置展示。
- “关于”保留为紧凑设置分类。
- 暂不加入 L3：Keychain、可配置扫描根目录、备份导入导出、更新回滚和设置配置档。

## 2. 冻结目标

1. 页面使用公共页面头部语义和项目现有主题 Token，不复制旧 Emoji 标题、表单和按钮样式。
2. 默认窗口采用“分类导航 + 当前分类内容”，避免七个区块全部展开形成约 2437px 长滚动。
3. 900 × 600 下分类导航切换为横向分段，内容保持单列，无页面级横向溢出。
4. 首屏提供 Sidecar、备份、通知和 GitLab 配置摘要，但不扩张为功能仪表盘。
5. 普通设置、只读运行信息、实验功能、危险操作和最高风险更新任务必须具有不同的信息层级。
6. 备份默认展示最近 3 条，待恢复状态始终可见，完整列表可以展开。
7. GitLab Token 只存在于页面局部表单和现有 SQLite 配置，不进入 Pinia 持久状态，不宣称已经加密。
8. 应用更新使用独立任务对话框承载步骤、进度、日志、失败和重试，不能降级为普通 Toast。
9. 所有基础控件优先复用项目二次封装组件；设置专用组合组件先留在页面目录。

## 3. 信息架构

正式页面冻结为六个分类：

1. **常规**：Sidecar 状态、重启、连接超时、Node 版本、项目扫描目录和菜单排序。
2. **数据与备份**：自动备份摘要、最近备份、立即备份、恢复、取消恢复和删除。
3. **外观与通知**：主题三态、通知开关、通知授权、测试通知和折叠的实验功能。
4. **Git 活动**：GitLab Token、默认作者、仓库列表和保存状态。
5. **高级**：应用更新、开发环境测试 Sidecar；正式构建不展示测试进程管理。
6. **关于**：版本、架构、端口、数据位置与现有介绍入口。

页面头部提供设置搜索。搜索只匹配设置名称和固定关键词，不搜索、索引或展示 Token、路径输入值等用户数据。

## 4. 菜单排序交互

- 使用紧凑排序列表，不再让 11 个菜单项各占一个大型设置行。
- 指针和键盘操作统一使用明确的上移/下移按钮，不提供拖拽排序。
- 上移/下移后立即持久化顺序并同步左侧菜单，后续可以补充方向键快捷操作。
- “应用首页”固定在最前，“系统设置”固定在最后；固定项必须有可理解的只读状态。
- 提供“恢复默认”，并使用公共确认组件。
- 菜单顺序仍由应用壳持有唯一权威，设置页不得复制第二套 localStorage 状态模型。

## 5. 实验功能边界

- Live2D 和点击粒子放入“外观与通知 → 实验功能”折叠区域。
- 两项默认关闭，并明确 Live2D 需要联网加载外部资源。
- 正式 Vue 页面只改变偏好；全局脚本、DOM 和监听由应用壳管理。
- 本轮不新增其他视觉特效。

## 6. 可靠性与风险基线

L2 视觉确认不取消以下实现要求：

- 页面进入时刷新 Sidecar、备份和权限等可变状态；卸载时取消页面请求和订阅。
- 连接超时保存成功后同步 `useSettingsStore` 与迁移期旧桥接缓存。
- 备份创建、恢复、取消恢复、删除分别维护操作状态，不共用一个模糊 loading。
- 恢复继续采用“暂存 + 重启换库”，并保留 pre-restore 副本语义。
- Sidecar 重启后统一更新 API 端口并重连 WebSocket。
- 更新任务接入共享 WebSocket client，并保留退出/重启兜底。
- 通知本地开关和 macOS 授权状态分开表达。
- 修正或统一测试 Sidecar 的启动/识别契约后，才实现开发进程管理。
- `settings.css` 按真实消费者拆分，确认无消费者后再删除；不能直接整文件移除。

## 7. HTML 原型验收范围

原型必须覆盖：

- 1280 × 720 暗色和亮色。
- 900 × 600 暗色和亮色。
- 六个分类切换和设置搜索。
- 状态摘要、普通设置行、只读信息、实验功能和危险操作的视觉层级。
- 备份最近 3 条与展开完整列表。
- 紧凑菜单排序的上移/下移操作。
- GitLab Token、作者、仓库行编辑器和未保存状态。
- 更新确认与任务进度对话框。
- 键盘焦点、弹窗关闭、减少动态效果和页面级无横向溢出。

原型只使用安全模拟数据，不连接正式 Sidecar、数据库或 Tauri，不执行重启、备份、恢复、通知授权、配置保存或应用更新。

2026-07-29 已生成 `design-preview/settings-l2.html`，原型包含：

- 六类设置导航、设置搜索和四项系统状态摘要。
- 常规页运行信息、连接超时和紧凑菜单排序。
- 最近 3 条备份、展开全部 7 条、恢复与删除确认。

- 紧凑关于分类。

内置浏览器自动验收结果：

- 1280 × 720 暗色、亮色下，页面、工作区和当前分类均无横向溢出。
- 900 × 600 暗色、亮色下，应用侧边栏自动收窄，分类导航转为横向分段；页面 `scrollWidth === clientWidth === 900px`。
- 六个分类在 1280 × 720 和 900 × 600 下逐一切换，所有分类 `scrollWidth === clientWidth`。
- “备份”搜索得到 1 条结果，点击后正确清空查询并跳转至“数据与备份”。
- 备份列表可以从最近 3 条展开为 7 条；超出可视高度时只在当前分类内部纵向滚动。
- 菜单“下移”兜底操作已验证，顺序从“应用首页 / 本地运行 / 部署面板”变为“应用首页 / 部署面板 / 本地运行”。
- Git 活动新增仓库后行数从 3 变为 4，并显示“有未保存修改”；保存后恢复“配置已保存”。
- 应用更新先显示影响说明确认，再进入三步任务进度对话框；900 × 600 下弹窗完整位于视口内且没有页面溢出。
- 控制台没有新增 error 或 warning。

自动验收只操作安全模拟状态，没有连接正式 Sidecar、数据库或 Tauri，也没有产生截图、报告等仓库内临时文件。

用户已确认原型整体效果并允许进入 PG4。

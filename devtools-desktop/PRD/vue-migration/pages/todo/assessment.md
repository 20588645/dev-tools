## 3. 当前页面目的与真实信息架构

页面当前实际是一个个人轻量任务面板：

- 左侧按 `todo / doing / done` 三种状态分组展示任务。
- 右侧展示和编辑当前任务标题、描述、子任务与状态。
- 新建任务时可以设置子任务和一次性提醒。
- 应用启动后每 30 秒检查一次已到期且未完成的任务。

页面副标题写的是“按项目分组记录待办事项”，但数据表、API 和页面均没有项目字段，实际只按状态分组。这是已确认的文案与功能不一致，不应在 Vue 迁移时继续保留该表述。

## 5. 数据模型与持久化边界

### 5.1 SQLite `todos`

| 字段 | 当前用途 | 迁移关注点 |
| --- | --- | --- |
| `id` | `todo-` 前缀的时间随机 ID | 保持历史数据兼容 |
| `title` | 任务标题 | 唯一必填字段 |
| `content` | 描述和子任务的混合文本 | 不是结构化 JSON |
| `status` | `todo / doing / done` | API 未校验白名单 |
| `remindAt` | ISO 时间字符串或空字符串 | 同时承担提醒和到期时间语义 |
| `createdAt` | 创建时间和列表排序 | API 固定按创建时间倒序 |
| `updatedAt` | 最近更新时间 | 当前列表显示创建时间相对值，不使用更新时间 |

### 5.2 `content` 的兼容编码

描述和子任务被序列化为：

```text
普通描述
[checklist]
- [ ] 子任务一
- [x] 子任务二
```

迁移时必须保持现有内容可读，不能直接改为 JSON 后清空或覆盖历史数据。若后续决定结构化子任务，应设计显式兼容读取和迁移策略，不能混入普通 Vue 架构提交。

### 5.3 本地提醒去重

已提醒任务 ID 存在 `localStorage: devtools-reminded-todos`，最多保留 200 个。该状态不在 SQLite，也不随数据库备份恢复。

当前只按任务 ID 去重，没有把提醒时间纳入 key。任务提醒触发后，即使未来增加修改提醒时间入口，同一个任务也不会再次提醒，除非额外清理 localStorage 中的 ID。

## 6. 已确认的可靠性与功能问题

### P0：状态与提醒可靠性

1. `loadTodos()` 捕获所有错误后直接写入空数组，加载失败、Sidecar 断开和真实空列表在 UI 中无法区分。
2. `todoLoaded` 声明后从未使用，页面每次进入都会请求，且没有加载、错误、重试或请求所有权状态。
3. 提醒轮询在旧脚本加载后常驻应用生命周期，没有可测试的启动/停止所有者。
4. 提醒只在应用运行时由前端每 30 秒检查；应用未运行期间不会由系统后台调度。
5. 已提醒状态只按任务 ID 去重；提醒时间变化、任务重新打开或状态重启不会自然生成新提醒。
6. 通知正文直接拼接原始 `content`，会把 `[checklist]` 和 Markdown 勾选语法展示给用户。
7. API 接受任意 `status` 和任意 `remindAt` 字符串，没有白名单或日期有效性校验。
8. 创建后没有编辑、清除或重新安排提醒的入口，提醒只能在新建任务时设置。

### P1：功能与表达一致性

1. 页面宣称“按项目分组”，实际没有项目模型，只按状态分组。
2. `remindAt` 同时承担“到期时间”和“通知时间”，但页面没有解释这两个语义是否相同。
3. 任务列表按创建时间倒序，不能手动排序，也没有优先级或明确的“今天 / 逾期”聚合视图。
4. 描述只在失焦时保存，没有保存中、保存失败、重试和离开保护。
5. 子任务每次编辑都重写整个 `content`，没有版本或并发保护。
6. 左侧快速状态按钮把任何非完成任务直接切到完成，绕过“进行中”状态流。
7. 批量清理已完成会永久删除记录，没有归档、撤销或回收站。
8. 新建弹窗把标题、子任务、日期、时间和自制弹层放入一个复杂全局对话框，操作密度高。

### P2：架构与维护

| 指标 | 当前数量 | 结论 |
| --- | ---: | --- |
| `todo.js` | 1101 行 | 页面、数据、提醒和日期组件耦合在一个全局脚本 |
| 全局函数 | 46 个 | 难以约束生命周期和单元测试 |
| JS 模板内联事件 | 40 个 | 依赖全局函数和隐式 `event` |
| `todo.css` | 1228 行 | 不应复制进 Vue SFC |
| `!important` | 690 处 | CSS 层叠已失控 |
| 页面专用媒体查询 | 0 个 | 最小窗口没有明确重排契约 |
| `:focus-visible` | 0 个 | 键盘焦点缺少统一规则 |
| `prefers-reduced-motion` | 0 个 | 动效没有减少动态适配 |

其他耦合：

- 依赖旧全局 `API`、`showToast`、`showConfirm`、`sendDesktopNotification` 和 `sysDialog`。
- 依赖 `app.js` 的 `switchPage('todo')` 激活。
- 自定义日期、时间、月历和 checklist 编辑器与业务逻辑混在同一文件。
- 使用全局 `document` 点击监听关闭弹层；Vue 迁移时必须建立挂载和卸载边界。
- 部分函数依赖浏览器隐式全局 `event`，可测试性和兼容性较弱。

## 7. 布局与样式问题

1. 主体始终使用双栏 `flex`，左侧权重 1.4、右侧权重 1；运行态已确认 900px 下仍不重排，详情仅约 304px。
2. 新建弹窗右侧提醒栏固定 260px，日期弹层固定 240px、时间弹层固定 180px。
3. 左右面板各自滚动，详情子任务又有 250px 内部滚动，任务较多时会形成多层滚动。
4. 任务删除和子任务删除主要依赖 hover 显示，对键盘和非鼠标操作不友好。
5. 大量硬编码 `rgba`、`#fff`、`#2563eb` 和页面私有阴影没有完全映射到正式语义 Token。
6. 顶部仍是旧 Emoji 标题、旧按钮和旧 Toolbar，没有使用正式 Vue `PageHeader` 和公共组件。
7. 页面样式没有 `prefers-reduced-motion`，但任务 hover、弹层和删除按钮存在位移、缩放或过渡。
8. 宽屏卡片使用满高布局，内容与底部操作之间形成过大空白；窄屏又没有把同一空间转换成单栏或主从切换。

## 8. 可访问性风险

以下是由 DOM 和 CSS 直接确认的风险，不能代替屏幕阅读器或键盘实测：

1. 页面标题使用普通 `div`，不是 `h1`。
2. 任务行、分组标题、圆形状态控件、日期触发器、时间触发器和月历日期主要使用带 `onclick` 的 `div` 或 `li`，不能自然获得按钮语义和键盘操作。
3. 详情描述使用 `contenteditable`，没有可访问名称、说明或错误状态关联。
4. 子任务删除默认 `display: none`，只有 hover 才出现，没有等价 `focus-within` 展示规则。
5. 自定义月历没有网格、日期按钮、当前日期、已选日期等 ARIA 语义。
6. 页面没有 `:focus-visible` 和统一焦点环。
7. 加载、保存、错误和提醒状态没有页面级 live region。
8. 16px、14px 和 18px 的状态/删除控件低于舒适点击目标尺寸。

## 9. 可复用的项目公共能力

正式 Vue 页面优先复用：

- 布局：`PageFrame`、`PageHeader`、`PageToolbar`、`PageSection`。
- 基础：`BaseButton`、`BaseIconButton`、`BaseBadge`、`StatusIndicator`、`BaseCard`。
- 表单：`BaseInput`、`BaseTextarea`、`BaseCheckbox`、`BaseSelect`。
- 反馈：`LoadingState`、`ErrorState`、`EmptyState`、`ConfirmDialog`、`AppToastHost`。

可能保留为待办页面私有组合组件：

- `TodoStatusGroup`
- `TodoListItem`
- `TodoDetailPanel`
- `TodoChecklist`
- `TodoEditorDialog`
- `TodoReminderField`

日期时间选择应优先评估 Naive UI 已有组件并通过项目适配层封装，避免迁移 500 行左右的自制月历和时间弹层代码。

## 10. PG0～PG1 结论

PG0 视觉与关键状态取证、PG1 页面 DOM、JS、CSS、API、数据库、localStorage、定时器、通知和公共组件研究均已完成。

当前页面核心 CRUD 已形成闭环，但不能直接等价迁移：

- 必须先决定宽屏空白和 900px 双栏压缩的布局方案。
- 必须冻结提醒能否编辑、重新提醒与应用关闭时的产品语义。
- 必须处理加载失败与空列表混淆。
- 必须决定父任务完成与未完成子任务的关系。
- 必须保持旧 `content` 格式和 SQLite 数据兼容。

本轮手动 E2E：**不需要**。目前只有文档取证，没有正式运行时代码变更。

## 1. 用户已确认的方向

- 优化等级选择 **L2：可信且聚焦的用量仪表盘**。
- 制作亮色、暗色和 900 × 600 窄窗口 HTML 原型。
- 暂不加入 L3-A 价格历史、L3-B 扫描任务化或 L3-C 异常数据诊断。
- 未定价时不再展示 `$0` 成本结论，明确显示“单价覆盖率 0% / 成本暂不可计算”。
- 在三种视觉探索中选择“总 Token 与趋势连续主视区、右侧关键指标纵列、下方构成与排名”的方向。
- 趋势图不保留底部区间滑动条，也不增加滚轮缩放；查看范围统一由顶部日期筛选控制。
- 在线价格同步改为“可靠匹配后直接覆盖本地单价”，不再生成候选后要求逐条手动应用。

## 2. 冻结的信息架构

1. 顶部保留页面标题、日期范围、应用筛选、同步状态、CC Switch 历史导入和“数据与价格设置”入口。
2. 总 Token 与趋势图形成一个连续主视区，不再拆成多张重复 KPI 卡片。
3. 右侧只保留请求总数、缓存输入占比和单价覆盖率三项关键指标。
4. 单价覆盖不足时显示紧凑说明，不再保留空成本构成图、零成本折线或零成本“最贵请求”。
5. Token 四类拆分合并为水平构成条。
6. 下方保留项目用量排名；价格不可用时使用“最大 Token 请求”替代“最贵请求”。
7. 模型、请求日志和价格设置合并为“数据探索”Tab，不再纵向堆叠三组独立表格。
8. 900 × 600 下使用单列纵向重排，表格只允许局部横向滚动，不产生页面级横向滚动。
9. 趋势图底部不放置 dataZoom 滑动条，避免与顶部时间范围筛选形成两套区间控制。
10. 价格同步结果展示来源、同步时间、已覆盖、未匹配和冲突数量；用户不再逐条选择候选。

## 3. HTML 原型范围

`design-preview/usage-l2.html` 使用安全模拟数据，包含：

- 1440 × 1024 暗色参考布局。
- 亮色、暗色主题切换。
- 900 × 600 窄窗口单列重排。
- 日期范围与 Claude Code / Codex 应用筛选。
- Canvas 趋势图和 Token 水平构成条。
- 趋势图不包含底部滑动条或滚轮缩放交互。
- 项目用量、最大 Token 请求和数据探索 Tab。
- 数据与价格设置弹窗，以及“同步并覆盖”的安全模拟交互。
- 导入按钮的原型安全提示，不连接正式 Sidecar 或数据库。
- 键盘焦点和减少动态适配。

原型不执行真实扫描、CC Switch 导入、单价保存、历史成本重算、订阅费用写入或任何正式数据修改。

## 4. 自动检查记录

- 1440 × 1024 暗色布局与用户选定参考图并排检查，信息层级、主区域比例和内容密度一致。
- 1440 × 1024 亮暗主题下 `body.scrollWidth === body.clientWidth === 1440`。
- 900 × 600 亮暗主题下 `body.scrollWidth === body.clientWidth === 900`，内容区 `scrollWidth === clientWidth === 813`。
- 900 × 600 下总 Token、趋势和三项关键指标按单列结构展示，无卡片重叠或页面级横向滚动。
- 趋势图底部滑动条已移除，Canvas 绘图区补足释放出的高度，没有遗留空白占位。
- 数据与价格设置弹窗可打开、关闭；数据探索模型、请求日志和价格设置 Tab 可切换。
- 点击“同步并覆盖”后，单价覆盖率、三个模型状态、价格提示和按钮状态会一次性切换为同步完成，不出现候选选择步骤。
- 日期范围和应用筛选可切换，趋势图与汇总模拟值同步更新。
- 浏览器控制台无新增 error 或 warning。
- 截图和并排对照图保存在系统临时目录，不进入仓库。

## 5. 正式价格同步契约

本次用户确认会改变现有 Sidecar 的价格同步语义，因此 PG4 必须把它作为独立、可测试的受控子步骤，不能只在 Vue UI 中隐藏旧候选列表：

1. `models.dev`、LiteLLM、OpenRouter 继续沿用现有来源优先级。
2. `verified`、`single-source` 以及存在主来源的 `conflict` 使用优先来源直接覆盖本地 `model_pricing`。
3. `unmatched` 不删除、不清零现有本地价格。
4. 所有可靠匹配模型批量写入后，只统一执行一次历史成本重算。
5. 同步接口返回 `applied`、`unchanged`、`unmatched`、`conflicts`、`sources`、`repriced` 和同步时间等摘要。
6. 正式页面不再获取或展示待应用候选，也不再提供逐条“应用候选”按钮。
7. 页面仍需显示来源、更新时间和同步摘要，避免自动覆盖变成不可观察的后台行为。

当前 HTML 原型只演示最终交互，不调用真实公开 API，不修改 Sidecar、SQLite 或历史成本。

## 7. PG4 之后的增补优化（用户提出，已实现并通过手动 E2E）

以下两轮都在 PG4 通过之后提出。前者含功能新增，本应退回 PG2/PG3，经用户明确要求「直接按上面的决定实现」后执行。

### 7.1 第一轮：功能与缺陷

1. **自定义日期区间**：新增「自定义」档，可选任意 start/end，支持「结束时间跟随当前时刻」。后端各接口本就接受任意 start/end 与三档 bucket，无需改动。
2. **环比对比语义**：自定义区间采用**等长前一段**（7/01~7/10 对比 6/21~6/30）。取「保住环比信息」而非「自定义时隐藏」，因为等长回退语义清晰可解释。预设档位（今天/近7天/本月）行为完全不变。
3. **bucket 自动分级**：≤2 天用 `min10`，≤40 天用 `hour`，更长用 `day`，避免长区间返回上万个点。
4. **自动刷新间隔**：关闭 / 10s / 30s / 60s，默认 30s，持久化到 `localStorage`。**刻意不做 CC Switch 的 5s 档**——每次刷新都会触发 `syncUsage()` 重扫日志文件，对本地 SQLite 是纯开销。
5. **顶部入口精简**：删除「数据与价格设置」按钮（与底部数据探索 Tab 重复）；「导入 CC Switch 历史」以 `v-if="false"` 隐藏但**保留全部代码与 service**，它是一次性历史迁移入口，需要时改回即可。
6. **排名样式**：去掉第一名的土黄圆点（`color-mix(--color-warning 82%, white)`，暗色发黄、亮色发棕），改为弱化等宽右对齐序号 + 前三名字重区分，排名列收窄、行高 42→38px。
7. **趋势图 Y 轴截断**：左边距由硬编码 44px 改为按 `measureText` 实测最宽刻度 + 14px 留白动态计算。
8. **趋势图悬浮详情**：原先完全没做（手写 Canvas 无 mousemove）。新增十字准线、数据点高亮与明细卡片。`UsageTrendRow` 已带齐 requests/input/output/cacheRead/cacheCreation/cost，无需改后端。

### 7.2 第二轮：视觉与交互

9. **悬浮卡片显示不全**：由「每应用一段、纵向堆叠」（双应用 12 行、272px）改为**指标为行、应用为列**的紧凑表格，行数固定不随应用数翻倍，宽度按列数自适应；无用量的应用不占列。
10. **数据系列色与语义色分离**：新增 `--color-series-1/2/3/muted`（亮暗分别定值），趋势线、Token 构成条、应用标签、项目占比条从 `--color-success` 迁出，Codex 由荧光绿 `#4ade80` 改为青绿 teal。**理由**：语义色只应表达状态好坏，当作品牌色大面积铺开会让「绿色=正常」失效，且高饱和绿在暗色下过曝、亮色墨绿发闷。`--color-success` 本身未改动，其他页面不受影响。顺带纠正「缓存输入占比」误用成功色（它是中性指标）。
11. **请求日志筛选器**：`.n-base-selection` 在 flex 容器内塌缩为 0 宽、只剩一条竖线，且空值显示默认「请选择」。补 `width: 100%` 与「全部模型」placeholder。该控件是有效的模型筛选功能，**未删除**。
12. **对话框内日期弹层无法点选**：Naive 日期面板挂在 body 下 `.v-binder-follower-container`，**内联** `z-index: 2000`，与对话框容器（20000）是兄弟节点。NDatePicker 无 `z-index` prop，外部 CSS 覆盖不了内联样式，项目规范又禁止新增 `!important`。方案：`BaseDialog` 增加 `below-overlays` prop，内嵌选择器时对话框降至 1900，让浮层自然在上。
13. **历史日期不可选**：`BaseDateTimePicker` 原先硬编码 `is-date-disabled` 禁用昨天之前所有日期（为待办「提醒时间」设计），用量统计查历史时全不可选。新增 `range` prop，默认 `future` 保持待办原行为，用量页传 `any`。
14. **连带修复既有缺陷**：待办「新建任务」对话框同样内嵌日期选择器且未传 `below-overlays`，其「提醒时间」原本也点不了日期。与第 12 项同根因，一并修正，并通过 Todo E2E 回归确认未破坏原有限制。

### 7.3 增补部分的验证

- 单测新增 8 项（等长回退、bucket 分级、刷新间隔持久化边界），全量 105 项通过。
- Usage E2E 由 4 项扩至 6 项（新增自定义区间、顶部按钮隐藏与默认间隔），并修正 1 项因删除顶部按钮而失效的旧用例；Usage + Todo 共 10 项全通过。
- lint、lint:tokens、build:frontend、`git diff --check` 全通过，新代码 0 个 `!important`。
- 修复过程中发现并修正一个自身引入的 bug：`Number(null) === 0` 且 `0` 是合法的「关闭」档，导致未设置过的用户默认变成关闭自动刷新而非 30s。

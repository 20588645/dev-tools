## 1. 评估范围与阶段边界

本页覆盖 Claude Code 与 Codex 本地会话日志的增量扫描、Token 与成本聚合、日期和应用筛选、项目与模型统计、请求日志、CC Switch 历史导入、订阅费用、模型单价和公开价格候选。

PG0～PG2 只进行运行态取证、代码与数据研究、问题分级和优化方案整理。本阶段：

- 不创建 `UsageView.vue`。

- 不触发“重新扫描”“导入 CC Switch 历史”“自动同步价格”“应用候选”“保存单价”或“订阅设置”。
- 只访问 `DEVTOOLS_TEST=1` 的 13900 测试 Sidecar；正常只读查询顺带执行的节流增量同步只写入 `sidecar/data-test`。
- 不访问正式端口 13456 和正式数据库。

本轮已读取：

- `frontend/index.html` 中 `#page-usage` 的旧 DOM、内联事件和脚本加载。

8. 请求日志当前达到一百多页；固定 15 行表格让用户很难从总览自然下钻到某个异常时段、模型或项目。
9. 900px 下顶部操作仍保持一行，内容区同时出现横向滚动；窄窗口没有明确的操作折叠和表格降级契约。
10. 亮暗主题没有发现双层边框、错色或图表主题未刷新，但亮色模式的次要文字和网格线对比偏低。

## 3. 当前页面目的与真实信息架构

当前页面实际承担四类职责：

1. **用量概览**：Token、请求数、成本、缓存命中、缓存节省和订阅回本。
2. **分析下钻**：趋势、项目、模型、最贵请求和原始请求日志。
3. **数据采集管理**：自动增量扫描、强制重扫和 CC Switch 历史导入。
4. **成本配置管理**：本地模型单价、远程候选、汇率和订阅费用。

页面把“日常查看”和“低频数据/价格维护”放在同一个纵向信息流中，是当前页面过长、操作层级混乱的根本原因。

## 5. 数据与成本口径

### 5.1 `usage_logs`

每条请求保存：

- 请求 ID、会话 ID、项目目录、应用类型和模型。
- 新增输入、输出、缓存命中和缓存创建 Token。
- 匹配到的价格模型、微美元成本和价格快照。
- 请求时间。

Claude Code 使用 assistant 消息 ID 去重。Codex 优先读取 `last_token_usage`，并把 OpenAI 口径中包含缓存的输入拆为“新增输入 + 缓存命中”；旧日志才回退到累计值差分。

### 5.2 当前指标口径

- `totalTokens = input + output + cacheRead + cacheCreation`。
- 当前“缓存命中率”实际是 `cacheRead / (input + cacheRead + cacheCreation)`，更接近“缓存输入占比”，不是按请求次数计算的命中率。
- 成本只有匹配到 `model_pricing` 时才会计算。
- 缓存净节省只统计已匹配单价的请求。
- “全部”范围的汇总查询覆盖全部记录，但趋势最多只返回最近 400 个日桶，UI 没有说明这个截断。

### 5.3 取证样本的价格覆盖

取证时今天的数据为：

| 指标 | 结果 |
| --- | ---: |
| 请求数 | 2003 |
| 总 Tokens | 303,362,868 |
| 模型数 | 3 |
| 已匹配单价模型 | 0 |
| 未匹配单价请求 | 2003（100%） |
| 成本 | $0 |
| 缓存净节省 | $0 |

三个未匹配模型为 `gpt-5.6-luna`、`gpt-5.6-sol` 和 `gpt-5.6-terra`。当前待确认远程价格候选为 0，说明“自动同步公开价格”不一定能解决本地 Codex 模型的单价覆盖。

因此当前页面不能把 `$0` 当作可靠成本结论，应明确显示“单价覆盖 0%，成本暂不可计算”。

### 5.4 价格与历史成本边界

现有安全边界值得保留：

- 远程目录只写入 `pricing_candidates`，不会静默覆盖本地单价。
- 用户必须主动点击才会应用候选。
- 用量记录保存价格快照。

仍需单独评审：

- 应用候选或手动保存会立即全量重算全部历史记录，并覆盖原价格快照。
- 负数价格在 Sidecar PUT 接口没有显式拒绝。
- “来源有差异”仍允许直接应用优先来源，没有二次确认。
- CC Switch 导入会合并价格并重算历史，操作前没有解释影响范围。
- 订阅月费只在 localStorage，不进入应用设置和数据库备份。

## 6. 数据流与生命周期

### 6.1 页面刷新链路

一次 `refreshUsage()` 会并行请求：

- 当前区间 summary、models、projects、top。
- 汇率。
- 本月 summary。
- 上一个对照区间 summary。
- 一个或两个应用的 trends。
- 以上完成后再请求 logs。

这会产生 8～10 个请求。summary、models、trends 和 logs 都会尝试触发一次 `syncUsage()`；15 秒节流减少了重复扫描，但同一页面刷新仍由多个独立响应拼成，缺少统一快照版本。

### 6.2 扫描链路

- Sidecar 启动 5 秒后强制扫描一次。
- Sidecar 每 5 分钟强制扫描一次。
- 查询接口每 15 秒最多顺带扫描一次。
- 页面激活时每 30 秒刷新。
- 强制扫描遍历 `~/.claude/projects`、`~/.codex/sessions` 和 `~/.codex/archived_sessions`。
- 文件读取、目录遍历、JSONL 解析和 SQLite 写入均在同步 Node 路径中执行。

日志总量增长后，首次扫描、大文件增量和全目录遍历可能阻塞 Sidecar 事件循环。当前接口没有任务 ID、进度、取消、最近错误或异常文件统计。

### 6.3 前端资源生命周期

- `setInterval` 只创建一次，但没有显式销毁。
- 主题 `MutationObserver` 只创建一次，但没有保存实例和断开方法。
- 每个 ECharts 初始化时创建 `ResizeObserver`，实例没有保存和 `disconnect()`。
- 图表只在无数据时 `dispose()`，页面离开和未来 Vue 卸载没有统一销毁入口。
- 快速切换时间范围或应用时没有 AbortSignal、请求序号或旧响应丢弃逻辑，较慢的旧请求可能覆盖较新的筛选结果。
- 刷新失败只有首次显示 Toast；页面没有 Loading、Error、Retry 或局部失败状态。

## 7. 已确认的问题与风险

### P0：数据可信度与安全边界

1. **未定价被显示为零成本**：当前样本 100% 未匹配单价，页面仍展示绿色 `$0.00`、成本折线、节省和 Top 10，结论具有误导性。
2. **本地日志字段直接进入 `innerHTML`**：模型名、项目目录和部分表格字段没有统一转义。本地仓库目录或日志模型字段若包含 HTML，可形成 DOM 注入；Vue 迁移必须使用模板插值或统一文本转义。
3. **历史成本可被一次操作全量改写**：保存单价、应用候选和 CC Switch 导入都会重算历史，当前缺少变更确认、受影响数量预览和回滚记录。
4. **同步扫描阻塞风险**：目录发现、文件读取和解析使用同步 API，数据量增长时可能拖慢整个 Sidecar。

### P1：可靠性与产品语义

1. 快速筛选、30 秒刷新和手动刷新没有请求所有权，存在竞态覆盖。
2. 多接口拼装没有一致快照；扫描恰好发生在中间时，不同卡片可能来自不同数据时刻。
3. 页面没有 Loading、Empty、Error、Retry 和局部失败状态，失败后可能保留旧值。
4. “缓存命中率”名称与实际 Token 占比口径不完全一致。
5. “全部”趋势最多 400 天，但汇总是全部历史，UI 没有披露范围差异。
6. 所有成本为零时，项目排序、模型排序和 Top 10 均没有实际成本排序价值。
7. 自动汇率会访问 `open.er-api.com`，页面只强调“本地解析”，没有显示远程汇率来源、时间和离线兜底状态。
8. 订阅费用只保存在 localStorage，不随应用数据备份。
9. 强制重扫和历史导入没有按钮级 loading/disabled 防重复提交。
10. 单价输入主要依赖浏览器 number 控件，服务端没有完整的非负数与合理范围校验。

### P2：架构与维护

| 指标 | 当前数量 | 结论 |
| --- | ---: | --- |
| `usage.js` | 861 行 | 请求、状态、渲染、图表、定价和分页耦合 |
| `usage.css` | 194 行 | 没有 `!important`，但缺少 900px 响应式契约 |
| ECharts vendor | 约 1.0MB | 仅 Usage 页面使用，全局脚本同步加载 |
| 页面请求 | 一次刷新 8～10 个 | 缺少聚合、竞态和局部状态 |
| Usage 专项测试 | 0 | 解析、价格、极值、竞态和图表销毁没有自动保护 |

其他维护问题：

- 顶部、按钮、筛选、下拉和卡片仍是旧 DOM/全局组件，不是 Vue 公共组件。
- 页面通过 20 多个 DOM ID 和多个全局函数更新。
- ECharts 依赖全局 `echarts`，没有 TypeScript 类型和按模块动态加载。
- 字符串模板、内联事件和 DOM 写入让状态难以单元测试。
- 当前 `getTopRequests()` 在成本相同为零时没有稳定的次级排序。
- Claude 解析使用位运算读取 Token，单条极端值超过 32 位整数时可能截断。

## 8. 布局与视觉问题

1. 固定头部包含两排内容，在 900px 高度 600 的窗口中占据明显可视空间。
2. 四个顶部操作没有按“日常操作 / 低频配置 / 数据迁移”分组。
3. 900px 下页面整体横向溢出；表格不应把整个页面推宽。
4. 280px 的空成本图表违反按内容密度布局原则。
5. 四张 Token 拆分卡与五张 Hero 小卡在窄窗口中形成大量卡片堆叠。
6. 项目、Top 10、模型、日志四组表格存在重复列和重复阅读任务。
7. 成本折线为零时仍占用第二 Y 轴和图例，降低趋势图有效信息比例。
8. Emoji 用于标题、卡片和按钮，不符合已经迁移页面的图标与文字层级。
9. 页面私有硬编码图表配色没有完全使用正式语义 Token。
10. 表格右侧成本列在窄窗口被裁切，固定头部又降低可用高度。

## 9. 可访问性风险

以下是截图和代码可确认的风险，不能替代完整键盘、屏幕阅读器和 WCAG 测试：

1. 页面标题是普通 `div`，不是 `h1`。
2. 时间范围和应用筛选没有 `aria-pressed`、单选组或 Tab 语义。
3. ECharts 没有可访问文本摘要、数据表替代或键盘下钻路径。
4. 颜色承担 Claude/Codex、成本和涨跌的重要区分，缺少始终可见的非颜色提示。
5. 加载、刷新、扫描完成、局部失败和价格应用结果没有页面级 live region。
6. 原生 select 和手写输入没有统一公共组件的标签、错误说明和焦点样式。
7. 横向滚动表格没有明确的滚动容器、可访问名称或窄屏列优先级。
8. 动画和图表重绘没有 `prefers-reduced-motion` 降级。
9. 亮色次要文字和细网格线存在对比度风险，但截图不能证明具体对比值或完整 WCAG 合规。

## 10. 可复用的项目公共能力

正式 Vue 页面优先复用：

- 布局：`PageFrame`、`PageTop`、`PageHeader`、`PageToolbar`、`PageSection`。
- 基础：`BaseButton`、`BaseIconButton`、`BaseBadge`、`BaseCard`、`BaseProgress`、`StatusIndicator`。
- 导航：`BaseSegmented`、`BaseTabs`、`FilterChip`、`BaseDropdownMenu`。
- 表单：`BaseInput`、`BaseSelect`、`FormField`。
- 反馈：`LoadingState`、`ErrorState`、`EmptyState`、`ConfirmDialog`、`AppToastHost`。
- 生命周期：现有 `useResizeObserver`，并在此基础上建立 `useECharts`。
- 服务：沿用 `apiClient`、AbortSignal、错误标准化和测试 Sidecar 端口注入。

建议的 Usage 私有结构：

- `UsageView.vue`
- `useUsageDashboard.ts`
- `usage-service.ts`
- `usage-format.ts`
- `UsageKpiOverview.vue`
- `UsageTrendChart.vue`
- `UsageProjectRanking.vue`
- `UsageTokenComposition.vue`
- `UsageDataExplorer.vue`
- `UsagePricingPanel.vue`
- `useECharts.ts`

`useECharts` 应负责初始化、容器 ResizeObserver、主题更新、KeepAlive 激活/停用、`clear()` 和 `dispose()`，不能把旧全局实例直接搬进 Vue。

### 11.2 优化

| 项目 | 优化方向 | 收益 | 风险/成本 |
| --- | --- | --- | --- |
| 顶部操作 | 只保留刷新/扫描状态；导入、订阅和单价进入“数据与价格设置” | 降低操作噪音 | 低 |

| 首屏结构 | 总 Token + 请求 + 覆盖率 + 缓存输入占比 + 趋势 | 首屏只展示可信结论 | 中 |
| Token 拆分 | 四张卡改为紧凑堆叠条或构成卡 | 减少卡片数量 | 低 |
| 成本区域 | 有价格时展示成本构成；无价格时显示短提示和配置入口 | 删除大面积空白 | 低 |
| Top 10 | 有成本时显示最贵请求；无成本时降级为最大 Token 请求 | 保持排序有意义 | 中，需要查询排序参数 |
| 项目统计 | 使用排名条，允许按 Token/成本切换 | 成本不可用时仍有价值 | 中 |
| 模型/日志/价格 | 合并为一个 Data Explorer 的 Tab | 缩短页面、减少重复表格 | 中 |
| 在线价格同步 | 可靠匹配成功后按来源优先级直接覆盖本地单价；未匹配保留旧值 | 删除逐条选择步骤 | 高，需要单独修改并测试 API/历史重算语义 |
| 请求日志 | 增加项目、模型、时间筛选和稳定分页状态 | 更容易定位异常 | 中 |
| 窄窗口 | 单列仪表盘；表格各自横向滚动或按列优先级降级 | 消除页面级横向滚动 | 中 |
| 反馈 | 分离 loading、error、empty、refreshing、stale 和 retry | 提升可信度 | 中 |
| 竞态 | AbortSignal + 请求序号 + 快速切换测试 | 防止旧响应覆盖 | 中 |
| 图表生命周期 | `useECharts` 统一 init/resize/theme/dispose | 防止资源泄漏 | 中 |
| 扫描状态 | 显示最近同步时间、扫描范围和异常文件数 | 用户知道数据是否新鲜 | 中高，需要 API |
| 汇率 | 显示来源、时间和离线兜底状态 | 透明说明远程依赖 | 低 |

### 11.3 删除或降级

| 项目 | 建议 | 原因 |
| --- | --- | --- |
| 零成本折线 | 未定价时不展示 | 数值没有解释价值 |
| 空成本构成大卡 | 改为紧凑提示 | 当前占据大量空间 |
| 零成本“最贵请求” | 改为最大 Token 请求或隐藏 | 排序语义不成立 |

| 趋势图底部滑动条和滚轮缩放 | 不保留，时间范围只由顶部筛选控制 | 避免两套区间控制，原型体验更直接 |
| 远程价格候选逐条应用 | 改为同步时批量自动覆盖可靠匹配项 | 删除不必要的二次选择 |

| Emoji 标题和按钮图标 | 使用项目图标体系 | 与迁移后页面统一 |

### 11.4 建议新增

| 项目 | 范围 | 价值 | 等级 |
| --- | --- | --- | --- |
| 单价覆盖率 | 已定价请求/Token 占比 | 解释成本可信程度 | L2 |
| 数据新鲜度 | 最近同步、扫描中、失败、部分异常 | 解释统计更新时间 | L2/L3 |
| Token 构成图 | 新增输入、输出、缓存命中、缓存创建 | 替代四张重复卡 | L2 |
| 最大 Token 请求 | 未定价时的 Top 列表降级 | 保留异常定位价值 | L2 |
| 数据浏览器 Tab | 模型、请求、价格统一承载 | 缩短页面 | L2 |
| 价格变更预览与确认 | 受影响记录、旧/新估算、回滚点 | 保护历史可信度 | L3-A |
| 后台扫描任务状态 | 任务 ID、进度、错误、取消、分块读取 | 避免阻塞和重复操作 | L3-B |
| 异常数据诊断 | 未匹配模型、解析失败、极值、截断提示 | 提升数据质量 | L3-C |

不建议本轮加入云端账单同步、团队成本分摊、预算审批、告警推送或跨设备同步。这些会显著扩大隐私、凭证和后端范围。

## 12. L0～L3 方案

### L0：可靠等价迁移

- 保留当前信息顺序和全部功能。
- 完成 Vue SFC、类型化 service、状态拆分、Loading/Error/Empty/Retry。
- 增加请求竞态保护和 `useECharts` 生命周期。
- 修复未转义文本、模型名重复和 900px 页面级横向溢出。

适合只完成架构替换；仍保留页面过长、配置入口混杂和无价格时的大量无效内容。

### L1：公共组件与视觉统一

- 包含 L0。
- 使用 PageHeader、Toolbar、BaseButton、BaseCard、BaseSegmented、BaseTabs、BaseSelect 和反馈组件。
- 统一正式 Token、图标、间距、焦点和亮暗主题。
- 低频配置操作降级到统一入口，表格使用局部滚动容器。

适合先统一风格；信息架构仍基本保持当前形态。

### L2：可信且聚焦的用量仪表盘

- 包含 L1。
- 首屏聚焦总 Token、请求、缓存输入占比、单价覆盖率和趋势。
- Token 四卡改为紧凑构成图。
- 成本区根据价格覆盖率自适应：可靠时显示成本，未定价时明确提示并给出设置入口。
- 项目统计支持 Token/成本口径。
- 模型、请求日志和价格设置合并为 Data Explorer Tab。
- 900 × 600 单列重排，不产生页面级横向滚动。
- 趋势图不保留 dataZoom 滑动条或滚轮缩放，统一通过顶部日期范围切换。
- 在线价格同步对可靠匹配项直接覆盖本地单价；未匹配项保留现有本地值。
- 先制作 1665 × 1184、默认窗口和 900 × 600 的亮暗主题 HTML 原型，再进入 Vue 实现。

这是当前推荐方案。它解决本轮截图确认的主要信息层级、零成本误导、空卡片和窄窗口问题。价格同步的自动覆盖属于用户在 PG3 新确认的后端语义变化，PG4 必须作为独立受控子步骤实现和验证，不能悄悄混入普通 UI 迁移。

### L3：数据可信度与扫描可靠性专项

L3 不作为一个大提交，应拆成三个独立子阶段：

#### L3-A：价格与历史成本完整性

- 增加价格覆盖率、模型别名和未匹配诊断。
- 应用价格前预览受影响记录与新旧估算。
- 保留可追溯价格版本，不直接覆盖历史快照。
- 把订阅费用迁入可备份的应用设置。

#### L3-B：扫描任务化

- 查询接口不再同步执行目录扫描。
- 扫描改为可观察的后台任务，提供进度、最近成功、错误和取消。
- 大文件分块读取，避免一次分配完整增量。

#### L3-C：异常数据诊断

- 记录解析失败、非单调累计值、未知模型和异常 Token。
- 为极大 Token、截断时间轴、重复记录和价格缺失建立测试。
- 在 UI 中显示数据质量摘要，而不是静默丢弃。

L3 涉及 API、SQLite、历史数据语义和性能，应在 L2 页面迁移之外单独确认、实现和手动 E2E。

### 13.1 PG3 新价格同步语义

PG1 记录的“远程目录只写候选、用户逐条应用”仍是当前正式代码事实，但不再是目标实现。PG4 冻结为：

- `models.dev` → LiteLLM → OpenRouter 继续使用既有来源优先级。
- `verified`、`single-source` 和存在主来源的 `conflict` 直接批量写入 `model_pricing`。
- `unmatched` 保留原本地价格，不能删除或清零。
- 批量应用完成后统一执行一次 `repriceAll()`，避免每个模型重复重算全部历史。
- 同步响应返回覆盖、未变化、未匹配、冲突、来源和历史重算摘要。
- Vue 页面删除候选列表和“应用候选”交互，保留来源、时间与同步结果展示。

这项变更涉及 Sidecar、历史成本和用户价格数据，正式实现后必须安排针对性的自动测试与真实 Tauri 手动 E2E。HTML 原型阶段只模拟结果，不发起真实同步。

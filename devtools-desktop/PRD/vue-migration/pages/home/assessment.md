# 应用首页迁移评估

> 页面：应用首页（Home）
> 评估日期：2026-07-21
> Page Gate：PG0 现状取证、PG1 代码研究、PG2 优化建议已完成；PG3 用户确认待完成
> 本文只记录现状、证据和建议，不冻结最终设计，也不授权开始 Vue SFC 实现。

## 1. 页面目的与使用场景

首页是应用启动后的总览入口，主要承担三类任务：

1. 让用户快速知道当前时间、当前工作空间和应用状态。
2. 把需要经常查看但不需要完整操作的摘要信息集中展示：今日用量、当前 IP 纯净检查、本周活动和今日活动节奏。
3. 作为低压力、偏沉浸式的工作入口，保留天气、每日一言和轻量视觉动效等情绪价值内容。

首页不是业务操作台。用量统计、纯净检查等卡片应提供清晰摘要并可跳转到完整页面；复杂筛选、历史管理、编辑和配置不应复制到首页。

## 3. PG1 代码与功能盘点

### 3.1 当前文件和职责

| 文件 | 当前职责 | 迁移目标 |
| --- | --- | --- |
| `frontend/index.html` | 保留 `#page-home` 和 `#vue-home-root`，由旧应用壳控制激活 | 由 `HomeView.vue` 作为正式 View 挂载，最终移除首页孤岛根 |
| `src/js/vue/home-page.js` | 全局 Vue Runtime、模板字符串、响应式状态、请求、计时器和导航 | 拆为 `HomeView.vue`、首页子组件、composable 和 service |
| `src/js/home.js` | 旧壳到 Vue 首页的挂载、刷新和运行状态兼容桥 | 迁移完成后删除；过渡期仅保留带删除 Gate 的 bridge |
| `src/css/pages/home-vue.css` | 首页 271 行私有布局、视觉和动效 CSS | 迁入 Vue 页面样式或页面级样式文件，删除旧选择器和未使用规则 |
| `src/js/app.js` | 页面切换、`WS` 事件、运行状态对账和首页刷新触发 | 迁移期间保留导航宿主；首页正式接管后只保留明确的 legacy bridge |

当前首页仍是“全局 Vue Runtime + 模板字符串”孤岛，不是 Vue 单文件组件架构。页面可以使用 Vue 响应式，但还不能复用 SFC 的类型、组件边界、依赖注入和单元测试结构。

### 3.2 卡片功能和数据来源

| 卡片 | 当前内容 | 数据真实性 | 交互/依赖 |
| --- | --- | --- | --- |
| Hero | 问候语、实时本地时间、武汉/UTC+8、工作空间、状态、固定文案和工作脉冲 | 问候语/时间/星期/空间真实；`FOCUS 4h 20m`、`整理 12 次`、`LAST OPEN 09:41` 当前为静态展示 | 每秒时钟定时器；无业务跳转 |
| 天气 | 31°C、多云、湿度、体感、风速、日落 | 当前为静态值，不能标记为实时天气 | 仅视觉展示 |
| 用量统计 | 今日 Tokens、较昨日变化、成本、缓存命中、请求数和装饰柱状条 | 主指标来自 `/api/usage/summary`；装饰柱状条为固定数组，不代表小时数据 | 点击/键盘操作跳转 `usage` |
| 纯净检查 | 当前 IP、风险值、位置、延迟和标签 | 来自 `/api/ipcheck/lookup`；失败时展示不可用状态 | 点击/键盘操作跳转 `ipcheck` |
| 本周节奏 | 近一周历史活动柱图、活跃日、峰值和平均活动 | `/api/history` 计算周内活动 | 只读；依赖当前时间和历史数据 |
| 每日一言 | 本地固定文案、换一条、收藏和两个统计数字 | 文案索引/收藏写入 localStorage；“今日记录 3 条”“收藏夹 12 条”为静态值 | `localStorage`；换一条有 220ms 过渡 |
| 今日灵感 | 设计情绪文案、三枚固定色彩标签、装饰轨道和活动频谱 | 活动提示和频谱来自 `/api/history` + `/api/run/history` 当日事件；标题、色彩标签和轨道为装饰 | 只读；动效受 `prefers-reduced-motion` 控制 |
| 昼夜进度 | 白昼百分比、昼夜状态、距离日出/日落和固定日出日落时间 | 当前时间真实；日出 05:28、日落 18:06 为固定值，不是位置/天气服务结果 | 每秒随时钟计算；只读 |

### 3.3 网络、事件、存储和定时器依赖

#### HTTP/API

- `GET /api/history`：用于本周节奏。
- `GET /api/run/history`：用于今日活动节奏。
- `GET /api/usage/summary?start=&end=`：用于今日用量。
- `GET /api/usage/summary?start=&end=`：再次请求昨日用量，以计算变化百分比；失败时降级为“今日实时”。
- `GET /api/ipcheck/lookup`：用于当前 IP 摘要。
- 通过旧全局 `API` 对象请求，页面目前没有 TypeScript 响应类型、取消请求或统一 service 边界。

#### WebSocket/旧应用壳

- `src/js/app.js` 的全局 `WS` 监听 `open` 和 `run-status`。
- 运行状态或重连后调用 `refreshHomeIfVisible()`，再通过 `window.DevToolsHomeApp.notifyRuntimeChange()` 刷新首页。
- 首页卡片通过全局 `switchPage()` 或查找 `.sidebar-item[data-page]` 回退导航。

#### localStorage

- `devtools-home-quote-index`：每日一言当前索引。
- `devtools-home-saved-quote`：当前收藏文案。

#### 生命周期

- 挂载时建立每秒时钟定时器并调用一次 `refresh()`。
- 卸载时清除时钟，但请求没有 AbortController；在快速切页或应用退出时，已发出的请求仍可能完成。
- `Promise.allSettled` 允许单个摘要失败，但错误只写入控制台，缺少卡片级可重试状态。

## 4. 当前问题

### 4.1 功能和数据问题

1. 天气卡片显示“实时”但使用静态数据，容易造成误导；应明确标记为“本地概览/示例数据”，或另立低优先级天气服务接入任务。
2. Hero 的 FOCUS、整理次数和 LAST OPEN 没有数据来源；继续展示会让用户误以为是实际统计。
3. 每日一言底部的记录数和收藏夹数量是静态数字；收藏功能只保存一条字符串，没有真实收藏列表。
4. 用量卡底部柱状图是固定高度数组，不是小时/模型维度数据；应避免把装饰图形误读为统计图。
5. 昼夜进度固定武汉日出日落，未说明位置来源；当用户位置或时区变化时数据不准确。
6. 首页摘要失败时没有统一 Loading/Empty/Error 视觉，部分卡片可能长时间停留在“检测中…”。
7. 用量与纯净检查只有整个卡片可点击，缺少明确的“查看详情” affordance 和可访问名称说明。

### 4.2 布局、视觉和可访问性问题

1. Hero 信息、装饰动效和工作脉冲占据较大面积，真实摘要的优先级不够突出。
2. 天气、用量、纯净检查三列在窄窗口会整列堆叠；这属于可接受的响应式策略，但需要明确内容最小高度和卡片内文本截断规则。
3. 部分小字号使用 8–10px，亮色主题下可读性和可访问性风险较高。
4. 卡片使用大量 `color-mix`、渐变、伪元素和动画，样式集中在 271 行页面 CSS，后续拆分时容易继续产生页面私有 token。
5. `#page-home.home-dashboard.active` 仍使用 `!important` 控制显示、尺寸和溢出，是旧壳与首页样式冲突的遗留点。
6. 动态装饰没有统一的动效预算；应保留低频、低幅度动效，并统一响应 `prefers-reduced-motion`。
7. 首页缺少页面级唯一 `h1` 语义；当前 Hero 标题为 `h2`，正式 SFC 化时应补齐页面语义。

### 4.3 架构和 CSS 问题

1. 业务、请求、导航和全局事件都在一个 304 行模板字符串文件中，无法独立测试。
2. `window.DevToolsHomeApp`、全局 `API`、全局 `WS` 和全局 `switchPage` 形成强耦合，切页和刷新行为不透明。
3. `home.js` 兼容桥只有 31 行，但它和 `app.js`、全局 Runtime 共同维持一套额外生命周期；正式迁移后应删除，而不是继续扩展。
4. 卡片重复使用 `vh-*` 私有类，公共 `BaseCard`、`StatusIndicator`、`LoadingState` 等尚未接入。
5. 当前样式通过 ID、页面状态类和 `!important` 兜底，迁移时必须先收敛到页面根作用域和 Token，不应把旧覆盖原样复制到 SFC。
6. 首页数据未建立 TypeScript 类型，API 字段如 `risk_score`、`cacheHitRate`、`startedAt` 直接散落在模板逻辑中。

## 5. 保留、优化、删除、新增建议

### 5.1 保留

| 项目 | 原因 | 优先级 |
| --- | --- | --- |
| 沉浸式 Hero、实时问候和本地时间 | 是首页识别度和情绪价值的核心 | P0 |
| 用量摘要卡与纯净检查摘要卡 | 用户已明确需要，且可跳转完整业务页 | P0 |
| 本周节奏和今日活动节奏 | 已有真实历史数据，能体现软件使用状态 | P1 |
| 每日一言手动切换和收藏 | 低压力内容，交互简单且用户已确认不自动轮换 | P1 |
| 亮色/暗色主题与默认窗口铺满策略 | 已经过多轮视觉确认，是现有体验基线 | P0 |

### 5.2 优化

| 项目 | 建议 | 收益 | 风险/成本 | 优先级 |
| --- | --- | --- | --- | --- |
| 卡片状态 | 统一接入 `LoadingState`、`EmptyState`、`ErrorState`，错误状态提供重试 | 降低“检测中”误解，失败可恢复 | 需要 service/composable 状态模型 | P0 |
| 用量摘要 | 保留总量、成本、请求数；柱形改为明确“近 7 次/小时”数据，拿不到数据时不绘制假图 | 真实性和可读性提升 | 需要确认 API 是否支持分桶；否则使用简化趋势线 | P1 |
| 纯净检查 | 增加“查看详情”文字或图标按钮，风险值配合 `StatusIndicator` 语义 | 提升可发现性和可访问性 | 低 | P0 |
| Hero 脉冲 | 只保留真实可计算指标（如今日活动次数、最近一次活动时间）；无来源的 FOCUS/整理次数删除 | 避免伪数据 | 需要确认指标口径 | P1 |
| 天气 | 短期改为“环境概览”或明确 mock；真实天气作为独立需求评审 | 避免误导和外部 API 依赖 | 低；接真实服务时为中 | P0 |
| 每日一言统计 | 删除静态“3 条/12 条”，或改为“已收藏/未收藏”真实状态 | 减少无意义文本 | 低 | P1 |
| 昼夜进度 | 将固定日出日落标注为工作区默认值，或接入已有位置设置；不要在本次迁移中扩展天气/地理服务 | 保留视觉价值并说明边界 | 低 | P1 |
| 字体与密度 | 取消 8px 级别正文，正文/辅助文字设置可读下限；数字使用统一 tabular-nums | 减轻阅读压力 | 低 | P0 |
| 动效 | 仅保留轨道、柱条和时间进度的低频动效；所有动效集中在页面动效 token | 科技感与可访问性平衡 | 低 | P1 |

### 5.3 删除

| 项目 | 原因 | 优先级 |
| --- | --- | --- |
| 无数据来源的 `FOCUS 4h 20m`、`整理 12 次`、`LAST OPEN 09:41` | 静态伪指标 | P0 |
| 每日一言静态记录数和收藏夹数量 | 与实际收藏状态不一致 | P0 |
| 将固定柱状数组当作统计图展示 | 容易造成数据误读 | P1 |
| `window.DevToolsHomeApp` 和 `home.js` 兼容桥 | SFC 接管并完成旧壳迁移后无消费者 | PG5 |
| 首页 CSS 中未被新组件使用的装饰规则 | 避免迁移后继续污染 | PG5 |

### 5.4 新增

| 项目 | 说明 | 是否需要后端/协议变更 |
| --- | --- | --- |
| 首页状态 composable | 统一时间、历史、用量、纯净检查、活动节奏和刷新状态 | 否 |
| `home-service.ts` | 封装首页 API 调用、响应归一化、超时和取消 | 否，沿用现有 API |
| 首页摘要类型 | 为 usage/history/run-history/ipcheck 建立最小响应类型 | 否 |
| 摘要卡可访问跳转 | 卡片使用显式按钮或链接语义，保留旧导航入口 | 否 |

| 真实天气或完整收藏列表 | 暂不纳入首页迁移；需要用户另行确认和独立评审 | 是/可能涉及持久化 |

## 6. 公共组件复用方案

首页使用 `PageFrame variant="immersive"`，不套普通 `PageTop`。卡片内部优先使用：

- `BaseCard`：统一表面、边框、hover/focus 和主题。
- `StatusIndicator` / `BaseBadge`：纯净检查、用量可用性和活动状态。
- `LoadingState`、`EmptyState`、`ErrorState`：所有异步摘要统一反馈。
- `BaseButton` / `BaseIconButton`：每日一言切换、收藏和跳转操作。
- `PageFrame` / `PageBody`：负责首页的 immersive 滚动边界，不复制旧 `#page-home` 的显示规则。

以下内容暂时保留为首页私有子组件，不提升为公共组件：Hero 环境图形、天气装饰、活动节奏图、昼夜圆环和每日一言星图。它们目前只有一个语义消费者，先通过组件边界隔离，不应为了“看起来可复用”提前抽象。

## 7. 建议的实现拆分

PG3 确认后，建议按以下边界实现：

```text
HomeView.vue
├── HomeHeroCard.vue
├── WeatherCard.vue
├── UsageSummaryCard.vue
├── IpPurityCard.vue
├── WeeklyRhythmCard.vue
├── DailyQuoteCard.vue
├── ActivityMoodCard.vue
├── DaylightCard.vue
└── useHomeDashboard.ts
    └── home-service.ts
```

`useHomeDashboard` 只负责页面状态、刷新和派生数据；service 只负责请求与响应归一化；每张卡片只负责展示和局部交互。导航通过已注册的 router/legacy bridge 接口调用，不在卡片中查找 DOM。

## 8. 风险与工作量

| 风险 | 影响 | 缓解方式 | 估计 |
| --- | --- | --- | --- |
| 旧壳和新 View 同时刷新 | 重复请求或状态不同步 | 迁移期只保留一个刷新入口，PG5 删除 bridge | 中 |
| API 字段不稳定/缺失 | 卡片展示异常 | service 层归一化、明确空值和错误状态 | 低～中 |
| 默认窗口高度变化导致裁切 | 破坏已确认布局 | 使用 CSS Grid minmax、内容驱动高度和两档截图验收 | 中 |
| 主题变量遗漏 | 亮/暗色对比失衡 | 复用 Semantic Token，运行 Token lint 和主题截图 | 低 |
| 动效过多或不尊重减弱动效 | 可访问性和性能风险 | 集中动效、低频、`prefers-reduced-motion` | 低 |
| 扩展天气、收藏或新统计 | 范围膨胀，拖慢架构迁移 | 单独记录为后续功能，不混入 PG4 | 中 |

预计纯架构迁移 + L0/L1 级小幅优化为 2～4 人日；若选择 L2 重新设计布局，需先制作亮暗主题 `prototype.html`；若选择 L3 并新增 API/持久化，必须拆为独立功能阶段和提交。

## 9. PG2 结论与待用户确认事项

当前建议默认以 **L1** 为起点：保留已确认的沉浸式首页布局和卡片语义，完成 Vue SFC 拆分、真实数据边界、状态反馈、公共组件接入、字体/间距/动效收敛，并删除明确的静态伪数据。

用户也可以选择：

- **L0**：只迁移架构、修复响应式和清理 CSS，不改变卡片内容。
- **L1（推荐）**：按本文建议做轻量视觉、数据真实性和交互一致性优化，不重新制作原型。
- **L2**：重新调整首页布局或交互；先制作亮暗主题 HTML 原型，确认后实现。
- **L3**：同时改变功能或数据流程；除原型外，另行确认 API、持久化、安全和工作量。

在用户确认 PG3 前，不开始创建 `HomeView.vue` 或删除当前首页实现。

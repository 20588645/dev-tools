# 自动更新机制联调测试 PRD

## 1. 目的
配合用户检查和测试“自动更新”系统的完整端到端逻辑，确认从代码提交、合并到自动构建拉取的完整闭环工作是否正常。

## 2. 测试提交说明
- **修改文件**：[index.html](file:///Users/ldy/personalTools/devtools-desktop/src/index.html)
- **修改内容**：微调更新气泡的鼠标悬停提示 `title` 属性。
  - **修改前**：`title="点击一键更新系统"`
  - **修改后**：`title="点击一键升级 DevTools 系统"`
- **作用**：无侵入式的小型前端属性微调，既能触发 Git 提交让远程产生领先，又完全不影响系统运行稳定性。

## 3. 合并与推送计划
1. 将修改文件 add 并 commit 到本地 `develop` 分支。
   - 提交说明：`feat(upgrade): 调整更新气泡 hover 提示，配合自动更新联调测试`
2. 推送本地 `develop` 到远端。
3. 切换到 `release` 并合并 `develop`。
4. 推送 `release` 到远端。
5. 切换回 `develop` 分支。

## 4. 预期测试结果
- 用户软件后台会自动检测到远程 `release` 的最新 commit hash 与本地不一致，重新在左下角渲染出“发现新版本”的紫色气泡（带有最新的美化和居中样式）。
- 用户点击气泡触发更新，后台 Sidecar 拉取此提交重新打包编译、覆盖安装并重启软件。
- 重启后，Hover 该更新气泡，提示文字显示为新修改的 `点击一键升级 DevTools 系统`。再次点击气泡时应提示“已是最新版本”并自动隐去气泡，即代表自动更新逻辑验证成功。

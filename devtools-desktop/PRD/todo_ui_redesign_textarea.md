# 待办任务清单输入框升级文本域与界面深度美化需求文档 (PRD)

## 1. 概述
用户反馈目前的子任务输入框高度太低，输入长内容时体验不佳，同时整个界面的展示效果较为单调不够美观。为提升交互体验与极客美学，决定进行两大核心重写：
1. **输入项文本域升级**：将弹窗内子任务单行 `<input>` 升级为自适应高度的多行 `<textarea>` 文本域，支持回车（Enter）直接添加并聚焦下一行，同时支持 Shift + Enter 换行输入。
2. **UI 视觉体系重构**：全面重新设计弹窗内的清单输入行以及看板卡片上的 Checklist 展现，使其具备现代 SaaS 级的暗磨砂、高对比发光的高级设计质感。

## 2. 功能与交互设计

### 2.1 文本域多态交互 (`todo.js` & `style.css`)
- **自适应拉伸**：利用自定义的 `autoGrowTextarea(el)` 函数，在初始化回显以及用户打字输入时，实时根据 `scrollHeight` 计算并动态调整 `textarea` 的物理高度，彻底杜绝滚动条，保证输入视野宽阔舒展。
- **快捷键分流**：
  - 单击 `Enter` 键：阻止换行，直接在当前行正下方插入一条全新空白子任务，并将焦点（Focus）精准切换过去。
  - 单击 `Shift + Enter` 键：允许在当前子任务文本域内正常换行，方便输入段落格式。

### 2.2 视觉美学重构设计 (`style.css`)

#### A. 弹窗清单编辑区 (Notion-Style Checklist Editor)
- **卡片化子项布局**：每个子任务行 `.todo-editor-checklist-item` 设计为轻量磨砂小卡片，采用 `align-items: flex-start;` 以确保在文字换行多行时，复选框与删除按钮能优雅地在顶部首行行高对齐。
- **去处黑底边框**：彻底摒弃全局 `input` 样式带来的丑陋的深黑色边框背景，将文本域底色设为完全透明 (`background: transparent`)，通过父卡片的 Subtle 悬停与获得焦点（`:focus-within`）边框外发光（呼吸蓝色渐变 `rgba(59, 130, 246, 0.3)`）来指示当前操作行，显得极其高雅简洁。
- **复选框与动作按钮**：复选框升级为高对比度、带圆角的复选按钮，删除键（`✕`）在鼠标 Hover 或行 Focus 时柔和渐显，防误触。

#### B. 看板卡片 Checklist
- **折行多行显示**：看板卡片上的子任务文字不再强制进行单行截断 (`white-space: nowrap`)，改用允许自动折行排版（`white-space: normal; word-break: break-word;`），确保在主看板上能一览无遗地查看详细长清单。
- **磨砂进度面板**：进度容器 `.todo-card-checklist-container` 升级为微光卡片，优化进度条渐变填充（采用 Primary 蓝紫色微光发光条），提升看板整理体验。

## 3. 验证计划
- **文本域多行测试**：输入超过 3 行的长文子项目，验证输入框是否平滑自动向下长高，无垂直滚动条。
- **回车键聚焦测试**：在第一行输入完毕后，按 `Enter` 键，确认能自动生成第二行并立即转移光标；按 `Shift + Enter`，确认能在第一行内正常换行。
- **视觉匹配度**：验证是否有小黑框残留，整个弹窗布局宽度是否 100% 优雅填充，看板卡片多行子任务是否美观展示。

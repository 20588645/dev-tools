# 笔记本页面样式异常并排及数据重叠问题修复 PRD (v2.0)

## 1. 问题描述
在上线新版 IP 检测页面后，部分用户反馈“笔记本”页面的笔记卡片出现异常的横向并排、错位，并且列表可见数据项减少（如原本 4 条数据仅显示了 3 条，部分卡片丢失）。

## 2. 根源分析
经全面排查和精确调试，造成该 Bug 的根本原因并非 CSS 样式直接污染，而是由**笔记正文的 HTML 未过滤渲染，造成的 DOM 模板语法结构破坏**：
1. **内容泄露到预览**：由于编辑器 `.nb-editor-content` 采用了 `contenteditable="true"` 的富文本编辑形式，用户在笔记内输入的任意 HTML 标签（如 `<div>` 等）在保存时以 `innerHTML` 形式提交。
2. **正则过滤不全**：后端和前端生成笔记列表的预览字段 `preview` 时，原正则 `replace(/[#*`>\-\[\]]/g, '')` 只处理了 Markdown 标记，**完全漏掉了对 HTML 标签的提取和过滤**，导致包含未闭合 HTML 标签的预览字段被直接拉取和存储。
3. **DOM 树混乱与层级坍塌**：在初次加载笔记本页面时，前端通过 `list.innerHTML = nbNotes.map(...)` 拼接并插入 DOM。一旦某条笔记的 `preview` 中包含有未闭合的 `<div>` 标签，浏览器在解析 HTML 字符串时就会产生严重的**标签配对错乱**，强行把原本并列在后面的笔记卡片 `.nb-note-item` 渲染成了当前卡片的子元素！
4. **现象映射**：
   - 因为子卡片被错误嵌套进了父卡片内部，导致在 Flex 行排版下，两个笔记卡片并排挤在同一个蓝色高亮容器内。
   - 被嵌套进去的笔记不再作为 `.nb-note-list` 的直接子节点，导致列表上的数据从视觉上“重叠并少了一条”。

## 3. 修复方案
**采用“前后端双层净化与转义 (Dual-Layer Sanitization & Escaping)”的机制防御 DOM 结构破坏**：
1. **后端过滤**：在 `sidecar/routes/notebook.js` 列表返回生成预览时，追加针对 HTML 标签的正则过滤：
   `n.content.replace(/<[^>]+>/g, '')`，从源头确保返回给前端的列表预览字段 `preview` 为纯文本。
2. **前端保存净化**：在 `src/js/notebook.js` 的 `nbSaveCurrentNote` 提交阶段，追加对 content 的 HTML 正则过滤后再存入 `note.preview`：
   `content.replace(/<[^>]+>/g, '')`。
3. **前端转义保障 (Fail-Safe)**：在 `src/js/notebook.js` 列表拼接渲染时，实现 `escapeHTML()` 安全转义函数，对渲染的 `${escapeHTML(n.title)}` 和 `${escapeHTML(n.preview)}` 进行实体字符替换（例如 `<` 替换为 `&lt;`），确保即便数据库内存在脏数据，也绝对不可能作为 DOM 标签被浏览器解析，从而杜绝任何嵌套崩溃。

## 4. 升级流程交互优化 (v2.1)
- **取消页面切换逻辑**：移除了原本点击侧栏更新药丸时切入“设置”页面的动作，简化了跳转。
- **直接就地拉起全局 Modal**：在 `settings.js` 中重构了 `startUpgrade(skipConfirm)` 函数，使其支持通过参数跳过二次确认（防止用户点击侧边栏确认后再点击一次设置确认的双重打扰）。
- **就地升级体验**：用户在侧栏药丸点击“立即更新”后，无需跳页，直接在当前页面层级拉起全局唯一的 `id="upgradeModal"` 进度遮罩层并开始轮询日志，确保交互链路最短、逻辑最清晰。

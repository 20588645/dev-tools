# 待办看板大尺寸双栏与自定义时间选择器需求文档 (PRD)

## 1. 概述
在上一轮的双栏改版中，文字书写手感大为提升。但用户指出，弹窗整体还是偏小，且原生的日期日历与时分选择器在 macOS/Tauri WebView 下的表现极其丑白或弹出过长滚条，破坏了极客暗色主题。因此，决定将弹窗物理大小整体升至软件宽高的 **`70%`**，并自主实现一套轻量级的自定义日期/时间选择器，杜绝使用系统原生控件。

## 2. 重设计目标
- **超视距工作窗 (70% 视口大小)**：
  - 弹窗宽度和高度统一锁定为整个软件的 **`70%`** (宽度 `70%`, 高度 `70%`)。
  - 左侧文本输入区域 (`.todo-content-textarea`) 实现真正的垂直高度高度撑满（`flex: 1`），让详细内容书写拥有超大视窗，极为便捷。
- **杜绝原生控件 (100% 自定义模拟选择器)**：
  - **自定义日历浮层**：摒弃原生的 `<input type="date">`，使用极轻量级的自定义日历面板 `div.custom-calendar-popover`。用户点击后在下方滑出暗色月历网格，支持切换年份和月份。
  - **模拟下拉时分**：摒弃原生的 `<select>`，使用 HTML 模拟的下拉列表。当点击小时或分钟时，弹出高斯模糊、带呼吸光圈的列表（`00` 至 `23` / `00` 至 `55` 步长为 5 ），完全契合系统的暗色主题，防止 WebKit 渲染出突兀的系统长条菜单。

## 3. 具体修改设计

### 3.1 双栏多态 HTML 更新 (`todo.js`)
- 弹窗内容中不再出现原生的 `<input type="date">`，替换为自定义触发器 `div.custom-date-trigger`（内含日历 SVG 图标和文字值）。
- 时分选择从 `<select>` 替换为 `div.custom-select-container`。原有 select 保持在 DOM 中但设置为 `display:none` 用作后台数据中转，保障底层校验和提交逻辑不需要发生任何修改（保持 100% 稳定性）。

### 3.2 自定义选择器交互算法 (`todo.js`)
- **日历网格渲染 (`renderCalendar`)**：根据选中的年月动态绘制 42 个单元格，支持上一月/下一月箭头交互，点击具体的单元格自动更新本地 `picker.dataset.date` 和标题文本，随后关闭面板。
- **时间选项选择 (`selectTimeVal`)**：小时和分钟点击后弹出列表，点选值后同步更新触发器显示，并在后台将对应的隐藏 `select.value` 改写。
- **Outside Click 自动收起**：绑定全局监听，一旦在弹窗外或弹窗内的空白处点击，自动收起全部展开的下拉和日历浮层。

### 3.3 CSS 重设与高颜值美化 (`style.css`)
- **70% 黄金宽高**：
  - `.todo-dialog-overlay .sys-dialog` 的 `width` 和 `height` 统一设为 `70%`，`max-width`/`max-height` 设定舒适上限。
  - 主内容区高度设为 `flex: 1; min-height: 0;`。
- **月历与下拉样式定义**：
  - `.custom-calendar-popover`：定位在输入框下方，设定高斯模糊，以深色为底，高亮今天的日期，选中项为 primary 渐变色。
  - `.custom-select-popover`：以列表形式展示数字，设置精致轻盈的暗色磨砂滚动条，防溢出。
  - `.custom-date-trigger` 与 `.custom-select-trigger`：在 focus 或悬停时有微妙的蓝色光晕及上浮。

## 4. 验证计划
- 打开弹窗，测量窗口比例是否占据了应用画面的约 70%。
- 输入超过一千字的长文任务详情，验证左侧编辑器高度是否自适应弹性拉高，有无滚动条遮挡。
- 分别点击自定义日期和时分模拟框，确认不会拉起系统的白色日历及纵向大原生菜单，而是出现高颜值暗黑月历和时分选择滚动板。
- 测试点击面板外的空白地方，月历与时分面板是否会自动关闭。

# PRD: 本地服务智能端口强释与多标签终端热恢复

本需求文档详述了 DevTools Desktop 在核心稳定性与故障自愈（Phase 1）中的优化方案。主要解决开发中两个核心痛点：一是端口占用导致的本地启动失败；二是由于应用退出、重启、闪退等引起的多终端 Tab 会话状态与工作路径丢失。

## 1. 业务背景与用户痛点

1. **端口冲突痛点**：在运行本地开发项目时，前端服务或 Node 后端常常因为某些孤儿进程或第三方服务（例如 Nginx、Apache、旧的 Webpack 进程）占用目标端口（如 `EADDRINUSE` 错误）而导致启动失败。用户需要繁琐地在终端使用 `lsof -i` 查出 PID 再手动 `kill`。
2. **终端状态丢失痛点**：开发工具往往会集成快捷终端命令行面板。但目前只要软件被关闭、崩溃或重新打包更新（开发时频繁热重启），用户之前打开的数个终端 Tab、以及每一个 Tab 所在的当前工作目录（Cwd）和配置好的 Node 版本就会全部丢失。每次重新打开软件都需要重新点击创建 Tab、切换路径，极大影响工作效率。

## 2. 核心功能规格

### 2.1 本地运行智能端口诊断与强释 (Smart Port Release)
本功能旨在提供“检测 -> 诊断提示 -> 一键强制释放并启动”的自愈闭环。

#### 2.1.1 占用诊断 API (`GET /api/run/port-owner/:port`)
* **路径与输入**：端口号 `:port` (1-65535)
* **执行逻辑**：
  1. 调用 `lsof -ti tcp:PORT` 查出占用该端口的 PID 列表。
  2. 针对首个占用 PID，执行 `ps -p PID -o user=,comm=` 查询启动该进程的用户和进程文件路径。
  3. 将 PID、所属用户、进程名称（Command）、进程完整路径作为 JSON 返回。
* **返回示例**：
  ```json
  {
    "inUse": true,
    "pid": 12894,
    "pids": [12894],
    "user": "ldy",
    "command": "nginx",
    "commandPath": "/usr/local/bin/nginx"
  }
  ```

#### 2.1.2 进程强释 API (`POST /api/run/force-release`)
* **输入**：`{ "pid": 12894 }`
* **执行逻辑**：
  1. 优先调用 `process.kill(-pid, 'SIGKILL')` 向该 PID 的**整个进程组**发送强制终止信号，以确保 Webpack/Vite 及其派生的子进程（npm/node）全数被清理。
  2. 如果由于进程组权限或平台原因失败，退化为 `process.kill(pid, 'SIGKILL')` 杀死单进程。

#### 2.1.3 前端 UI 诊断卡片与自愈交互
1. **自动诊断触发**：在用户通过“启动运行”或“快速启动”按钮运行本地项目时，如果抛出启动错误（如 `API.post` 请求失败，或进程启动后发生退出），前端将基于当前项目的端口号（如 8080）自动请求 `GET /api/run/port-owner/:port` 诊断。
2. **诊断气泡提示**：若确认端口被占用，则在项目卡片的“尚未运行”面板内展示高对比度的诊断信息警告气泡（样式匹配黄色 `--warning-subtle`），并精准展示：
   `⚠️ 端口 8080 被 nginx(PID: 12894) 占用`
3. **自愈按钮**：气泡右侧渲染 **“一键释放并启动”** 按钮。
4. **一键释放并启动流程**：点击按钮，发起 `/force-release` 释放端口后，自动无缝触发 `startLocalRun` 启动当前项目。

### 2.2 终端多标签会话持久化与热恢复 (Hot Terminal Session Recovery)
本功能旨在使终端 Tab 拥有在应用任意关闭、崩溃、更新重启后恢复原状（断点续传）的能力。

#### 2.2.1 数据库结构与会话模型
本地 SQLite 中初始化 `terminal_sessions` 结构：
```sql
CREATE TABLE IF NOT EXISTS terminal_sessions (
  id TEXT PRIMARY KEY,       -- 使用前端随机生成的 tabId 
  name TEXT NOT NULL,        -- Tab 标签名
  cwd TEXT NOT NULL,         -- 当前工作目录
  nodeVersion TEXT DEFAULT '',-- Node.js 版本（如果有的话）
  createdAt TEXT DEFAULT (datetime('now')),
  sortOrder INTEGER DEFAULT 0
);
```

#### 2.2.2 终端会话 API (`/api/terminal/sessions`)
* `GET /`：按 `sortOrder` 升序获取持久化保存的所有终端会话。
* `POST /`：新增/保存新创建的终端会话。
* `PUT /:id`：在 Tab 标签重命名或 pty 内部路径变更时更新 `cwd` 或 `name`。
* `DELETE /:id`：在用户手动关闭 Tab 时，从 SQLite 中移除会话。

#### 2.2.3 终端当前工作目录同步 (PTY Cwd Sync)
* **监控机制**：在 Sidecar (node pty 进程) 端，由于无法直接监听到 Shell 内部 `cd` 引起的路径变更，当且仅当用户输入中含有 `\r` (即敲回车键) 时，Sidecar 会使用系统原生的 `lsof -p <PTY_PID> -a -d cwd -Fn` 查询底层 shell 进程当前关联的 `cwd` 真实路径。
* **路径同步**：一旦获取到更新的 Cwd 路径，自动向 SQLite 更新当前 Tab 对应的会话 `cwd` 数据。

#### 2.2.4 会话重连还原生命周期
1. **新建/关闭**：前端在点击 `＋` 新建终端 Tab 时保存至 SQLite；点击 `x` 关闭时销毁。
2. **初始化还原**：每次软件加载“快捷命令”页时，自动从 SQLite 加载历史终端 Tab。遍历还原出多个 xterm.js 实例，且令每个实例的 pty 底层工作目录初始路径精确指向其在数据库中记录的最后一次工作目录（Cwd），从而实现热重连与现场还原。

## 3. 验收与验证方案

### 3.1 智能端口冲突诊断与一键释放验证
1. 用 Python 或命令行在后台占用项目预设的 8080 端口：`nc -l 8080` 或 `python3 -m http.server 8080`。
2. 在本地运行面板中点击“启动运行”该项目（其配置的端口设为 8080）。
3. **预期结果**：卡片启动失败，并在下方展示“⚠️ 端口 8080 被进程 XXX (PID: XXXX) 占用”的黄色气泡和“一键释放并启动”按钮。
4. 点击“一键释放并启动”，原有进程应该被强杀释放，本地服务随之正常启动进入运行状态。

### 3.2 终端会话热恢复验证
1. 打开“快捷命令”页，点按 `＋` 创建 3 个终端标签页。
2. 在第 2 个标签页中输入 `cd /tmp` 切换工作路径；在第 3 个标签页输入 `cd ~` 切换路径。
3. 强制退出并重新打开软件（例如执行编译更新，或者在命令行强杀应用）。
4. **预期结果**：重新打开“快捷命令”页后，终端标签自动还原为 3 个，且第 2 个标签页的 Shell 默认路径处于 `/tmp` 目录下，第 3 个处于家目录下，无需用户手动初始化路径。

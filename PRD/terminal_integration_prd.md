# 快捷命令页面集成终端面板需求文档 (PRD)

## 1. 背景与目标
在前端开发联调和项目构建中，开发者高频使用终端。虽然目前 `DevTools Desktop` 提供了快捷命令的一键执行，但现有的实现是通过 `child_process.exec` 在后台运行并返回静态输出，这存在以下问题：
1. **无法交互**：遇到需要用户确认（[y/n]）或交互式输入的命令时，程序会处于等待或假死状态。
2. **无实时反馈**：长耗时命令（如依赖安装、复杂构建）无法实时显示日志进度。
3. **不支持复杂控制**：无法使用 Ctrl+C 中断，无法使用 vim 等终端工具。

本需求的的核心目标是：**在“快捷命令”页面集成一个全功能的 Mac 终端面板，保留现有快捷卡片的同时，实现与终端的深度联动，让命令在终端内交互式、可视化地实时执行。**

## 2. 核心功能需求

### 2.1 终端面板基础功能
1. **全交互式 Shell 会话**：
   - 默认载入系统的 `/bin/zsh`（macOS 默认，若失败退回到 `/bin/bash`）。
   - 支持完整的键盘输入、回车执行、退格删除、Tab 自动补全。
   - 支持快捷键响应（Ctrl+C 中断、Ctrl+R 历史搜索等）。
   - 支持 ANSI 颜色字符和样式高亮显示。
2. **终端生命周期控制**：
   - 提供“清除屏幕”(Clear) 按钮，一键清空终端显示。
   - 提供“重启终端”(Reset) 按钮，强制杀掉当前 Shell 进程并重新开启一个全新的 Shell 交互窗口。
3. **窗口自适应 (Resize)**：
   - 终端能够自适应容器大小，在窗口大小发生改变时自动调整列数(Cols)和行数(Rows)。

### 2.2 快捷命令与终端联动
1. **一键发送执行**：
   - 点击快捷卡片上的“▶ 执行”按钮，系统读取命令内容，并**自动将其作为键盘输入发送到终端面板中，尾部追加回车符 `\r` 触发执行**。
2. **参数化命令填充**：
   - 对于带有占位符（如 `${port}`）的命令，如果卡片有参数输入框，在用户填入参数并点击执行时，自动替换占位符并将最终拼装好的命令发送到终端。
3. **Sudo 密码辅助输入（可选）**：
   - 允许用户配置 sudo 密码，并在终端遇到 `Password:` 提示符时自动尝试填入（或者由用户在终端直接输入，保证绝对的自由度）。

## 3. UI 交互设计

*   **布局结构**：
    *   页面采用垂直分栏布局：
        *   **上部栏**：保留快捷命令卡片网格，展示预设快捷命令。
        *   **下部栏**：终端面板区。占页面高度的 40% - 50%。
    *   终端面板顶部带有小控制条（包含标题 `macOS Terminal`，`Clear` 按钮，`Reset` 按钮，连接状态指示灯）。
*   **设计美学**：
    *   配合 DevTools 全局深色极客风（Glassmorphism，暗色微光边缘）。
    *   终端背景采用 `#0c1017` 或黑色半透明，字体使用 `JetBrains Mono`, `Monaco` 或系统默认等宽字体，字体颜色设为绿/淡蓝等微发光色。

## 4. 技术实现方案参考
1. **前端渲染**：使用 `xterm.js` 核心库及 `xterm-addon-fit` 插件。
2. **后端 PTY 桥接**：在 Node.js Sidecar 中通过 `node-pty` 库 spawn 真正的 macOS 终端进程，并通过 WebSocket 协议双向实时管道传输 stdin/stdout 字节流。
3. **兜底策略**：在 node-pty 加载失败或不支持的环境下，自动降级为标准的 `child_process` 双向管道通信（虽然不支持部分 TTY 交互，但能保持基本的命令行输入输出）。
